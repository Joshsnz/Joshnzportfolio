Log & Bark Computer Vision Pipeline

Industrial computer vision pipeline for reducing manual bark inspection by automating log detection, full-surface reconstruction, bark-region segmentation, and final review overlays.

The system detects when a log appears in video, groups the positive frame interval, stitches those frames into one continuous surface image, then segments the log body and bark regions for bark-percentage analysis.

Primary value: designed to target a 70–80% reduction in manual inspection effort by turning a slow visual review process into an automated detection, stitching, segmentation, and overlay workflow.

This is an operational target rather than measured production analytics, but it frames the project around the business problem: process more logs with less repetitive manual review.

Problem and solution

The user problem

Manual bark inspection is repetitive and difficult to scale. A log moves through the camera view, but the useful information is spread across many frames. To estimate bark coverage, a reviewer needs to identify the log, reconstruct its visible surface, and inspect irregular bark patches.

This project turns that process into an automated computer vision workflow. It first detects the useful frame interval, stitches those frames into a full log image, then runs segmentation models to produce a final bark-and-boundary overlay.

There are two separate “log” tasks in the system. The first is frame-level log presence detection, which happens before stitching. The second is log-boundary segmentation, which happens after the stitched image already exists.

Development was carried out in a Windows + WSL workflow. The edge-facing video stage was designed around Jetson-class deployment, while the heavier segmentation stage was trained and evaluated with GPU tooling.

System summary
Six-component hybrid pipeline

The full system is more than two YOLO models. It combines a classical frame-level detection pipeline with two downstream segmentation models.

  • Frame stage: ROI differencing, EfficientNet feature extraction, fitted scaling, PCA reduction, and RBF SVM classification.
  • Stitching stage: positive frame interval grouping and full-log image reconstruction.
  • Segmentation stage: one YOLO model for log-boundary segmentation and one YOLO model for bark-fragment segmentation.
  • Log boundary: Phase 2 — Unfreeze selected as best checkpoint.
  • Bark fragments: Phase 3 — Fine-tune selected for cleaner visual fusion.
  • Output: stitched log with red outer boundary, white bark outlines, and bark-percentage analysis support.

Pipeline order — from video to bark percentage

The pipeline has two different log-related stages. First, it detects whether a log is present in video frames. Later, after stitching, it segments the outer log boundary. The split into left/right halves happens after stitching, not before frame-level log detection.

1. Video/frame-level log detection: process a region of interest, isolate motion with frame differencing, extract EfficientNet features, apply fitted preprocessing and PCA, then classify frames as log/no-log using an RBF SVM.
2. Positive frame interval grouping: group consecutive positive frames into the interval where the log is passing through the camera view.
3. Stitched full-log image creation: stitch the positive frames horizontally into one long raw stitched image that represents the visible log surface.
4. Split stitched log into overlapping left/right halves: after detection and stitching are complete, split the raw stitched image so segmentation can run at a useful resolution.
5. Run log-boundary YOLO segmentation: segment the outer log body on each overlapping half. This is boundary segmentation, not the initial video log/no-log detection step.
6. Greenify and crop detected log body: convert predicted polygons to masks, smooth them, crop both halves to a shared top/bottom range, and replace non-log background with a consistent light-green fill.
7. Split cropped halves into bark-inference quarters: divide the normalized halves into smaller tiles so bark fragments can be inferred with more local detail.
8. Run bark YOLO segmentation: detect bark fragments on each quarter tile.
9. Restitch, fuse masks, and support bark-percentage calculation: map bark masks and log-boundary masks back into stitched-log coordinates, draw the final overlay, and prepare the output for bark-percentage analysis.
Stage A — Jetson: Video → Positive Log Frames → Stitched Logs

1. Video/frame-level log detection: ROI and frame differencing

The first stage detects whether the log is present in the video frames. It reduces the video problem to the area where logs appear, then differences consecutive frames so the moving log is emphasized while the mostly static background is suppressed.

2. EfficientNet features, PCA, and SVM classification

A frozen EfficientNet model acts as a feature extractor. The features are standardized, reduced to four principal components with PCA, then classified with an RBF-kernel SVM to produce a frame-level log/no-log signal.

SVM decision-score note: the decision plot should be interpreted with the labelling process in mind. Some frames are labelled from the full log interval, but the region of interest can lag slightly behind the full-frame log presence. A few blue points crossing the threshold are therefore acceptable in this context, because the downstream interval grouping and stitching logic is tolerant to small frame-level ambiguity.

3. Positive interval grouping and full-log stitching

Consecutive positive frame predictions are grouped into log intervals. Frames inside each interval are then stitched horizontally to reconstruct the passing log surface. This stitched image is the input to the later segmentation stage.

Stage B — GPU: Stitched Log → Log Boundary + Bark Segmentation

4. Log-boundary segmentation setup

By this point, frame-level log presence has already been detected and the full-log stitched image has already been created. Stage B is about segmenting the outer log body and bark fragments from that stitched image.

5. Split stitched log into overlapping halves

The already-stitched log image is split into left and right halves with a small horizontal overlap. This split happens after video detection and full-log stitching. The overlap helps prevent boundary discontinuities at crop edges where segmentation models can become less reliable.

6. Run log-boundary segmentation, then greenify and crop

YOLO predicts the outer log body on each overlapping half. After that, polygons are converted to masks, smoothed, and used to crop both halves to a shared top/bottom height. Non-log areas are filled with a uniform light-green background to prepare the image for bark segmentation.

  • Run YOLO log-boundary segmentation on each overlapping half.
  • Convert YOLO log polygons to binary masks.
  • Morphologically smooth the log mask.
  • Find the bounding rectangle of the log.
  • Use shared top and bottom crop bounds across both halves.
  • Fill non-log background with a consistent light-green value.
  • Save offsets so polygons can be aligned again during final fusion.

7. Bark segmentation setup

Bark segmentation uses polygon masks for bark fragments. Each normalized half is split again into quarters, increasing effective resolution for texture-level bark detection.

8. Inference geometry and final fusion

The strongest part of the approach is the tiled inference and coordinate reconstruction. Instead of forcing a long stitched log through one compressed segmentation pass, the pipeline splits the already-stitched image into manageable pieces, predicts at higher effective resolution, and maps all masks back into the original stitched-log coordinate system.

1. Start from one stitched full-log image.
Stage A has already detected the log in video, grouped positive frames, and stitched them into a long full-log surface image.
2. Split the stitched log into overlapping left and right halves.
This split is for high-resolution boundary segmentation. It happens after frame-level detection and full-log stitching are complete.
3. Run log-boundary YOLO segmentation on each half.
The log model predicts the outer log body on the left half and the right half. These masks are later merged into one full-log boundary.
4. Greenify and crop each detected log half.
Non-log background is replaced with a consistent green fill, each half is cropped to a shared top/bottom height, and offsets are saved so predictions can be transformed back.
5. Split each cropped half into two bark-inference quarters.
The left half becomes two bark tiles, and the right half becomes two bark tiles. This produces four bark-inference tiles.
6. Run bark YOLO segmentation on all four quarters.
Running bark inference on quarters preserves texture detail and avoids compressing the full stitched log into a single low-resolution model input.
7. Restitch the four bark predictions.
The bark quarters are restitched into left/right halves, then the halves are aligned into full-log coordinates. The saved crop offsets and split offsets keep the masks geometrically consistent.
8. Fuse final output and support bark-percentage analysis.
The merged log boundary is drawn in red, bark fragment outlines are drawn in white, and the aligned masks support bark-percentage calculation on the stitched log surface.

Approach assessment: this tiled strategy is a strong practical solution for this problem. Long stitched logs are awkward for a single segmentation pass because resizing can destroy bark detail. Splitting into halves and then bark quarters preserves detail, improves local inference quality, and makes the final output visually stronger. The tradeoff is more coordinate bookkeeping, but the final stitched outputs show that this geometry-management approach worked well.

12. Explainability and model behaviour

Why frame differencing helps

The conveyor background is mostly static while logs move through the frame. Differencing consecutive frames suppresses background information and emphasizes motion, making the log/no-log classifier easier to train.

Why some SVM score points cross the line

Some blue points above the decision line were acceptable because labels were based on broader frame/log-interval timing, while the ROI did not always show the log clearly at the same moment. The interval grouping stage is tolerant to this kind of small frame-level ambiguity.

Why PCA + SVM is useful on edge hardware

EfficientNet features are high dimensional. PCA compresses them into a small representation, and the SVM performs lightweight binary classification suitable for Jetson-class deployment.

Why splitting happens after stitching

The pipeline first detects positive video frames and stitches them into a full-log surface image. Only after that does it split the stitched log into overlapping halves for high-resolution log-boundary segmentation.

Why tiled segmentation worked well

Splitting the stitched log into halves, then splitting each half into bark quarters, preserved detail that would be lost if the full stitched log were resized into one model input. This is especially important for bark, where the target regions are small and texture-like.

Why bark metrics are lower than log metrics

The log boundary is one large continuous object. Bark appears as many small, fragmented, texture-like regions with subjective boundaries. Strict mask IoU scores are therefore lower for bark even when the visual output is useful for downstream bark-outline fusion.

Why checkpoint selection matters

The selected model should be chosen from validation behaviour and downstream output quality, not simply the final epoch. Log uses Phase 2; bark uses Phase 3 for cleaner qualitative fusion while noting Phase 2's stronger strict mask mAP.
