Log & Bark Computer Vision Pipeline

A two-stage industrial computer vision pipeline for detecting logs in video, stitching continuous log images, segmenting the main log boundary, detecting bark regions, and generating a final annotated output for bark-percentage analysis.

Project summary

This project was designed for an industrial log-processing workflow where the system needs to identify when a log enters the camera view, stitch the relevant frames into a continuous log image, then segment both the log boundary and bark regions.

The architecture separates lightweight edge detection from heavier GPU-based segmentation. Stage A runs on Jetson-class hardware and detects log intervals in video. Stage B runs on GPU and performs segmentation over stitched log images.

The final output combines bark outlines with a unified red log boundary, producing a visual result that can support downstream bark-percentage estimation.

Pipeline overview

The notebook describes a two-stage system: Jetson-based video detection and frame stitching, followed by GPU-based log and bark segmentation.

1. Video input and region of interest
Only the region where the log appears is processed, reducing background noise and computation.
2. Frame differencing
Consecutive frames are differenced so moving logs stand out against a mostly static background.
3. EfficientNet feature extraction
A frozen EfficientNet model is used as a feature extractor for compact image representations.
4. Standardization, PCA, and SVM
Features are standardized, reduced to four principal components, and classified as log/no-log with an SVM.
5. Log interval detection and stitching
Consecutive positive frames are grouped into intervals and stitched horizontally into full log images.
6. YOLO log boundary segmentation
The stitched log is split into overlapping halves and the outer log boundary is segmented.
7. Bark segmentation and final fusion
Bark regions are segmented, restitched, aligned with the original geometry, and combined with a unified red log outline.

Explainability and model behaviour

Why frame differencing helps

The conveyor background is mostly static while logs move through the frame. Differencing consecutive frames suppresses background information and emphasizes motion, making the log/no-log classifier easier to train.

Why PCA + SVM is useful on edge hardware

EfficientNet features are high dimensional. PCA compresses them into a small representation, and the SVM performs lightweight binary classification suitable for Jetson-class deployment.

Why overlap is used for segmentation

Large stitched logs are split for segmentation. A small overlap reduces boundary failures near crop edges and helps preserve continuity when the halves are merged.

Why Phase 2 is the best checkpoint

Phase 2 gives the strongest balance of high precision, high recall, and strict mAP. Phase 3 remains strong early but shows later instability, so best-checkpoint selection is more important than final-epoch reporting.

What this project demonstrates

End-to-end ML pipeline design

The project combines video processing, feature extraction, classical ML, neural segmentation, post-processing, and final visualization.

Hybrid classical + deep learning approach

Instead of using one model for everything, the system combines EfficientNet, PCA, SVM, YOLO segmentation, morphology, and geometric union.

Industrial computer vision framing

The pipeline is built around a real inspection-style problem: detecting logs, preserving full-surface geometry, and identifying bark regions.
