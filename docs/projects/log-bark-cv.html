Log & Bark Computer Vision Pipeline

A two-stage industrial computer vision pipeline for detecting logs in video, stitching continuous log images, segmenting the main log boundary, detecting bark regions, and generating a final annotated output for bark-percentage analysis.

Project summary

This project follows the same linear structure as the original notebook: first detect logs from video on Jetson-class hardware, then stitch log intervals into full surface images, then run GPU-based segmentation for the log boundary and bark regions.

The pipeline is built around an industrial inspection problem. A moving log passes through a camera view, the system identifies the relevant frame interval, reconstructs the visible log surface, segments the full log body, detects bark fragments, and fuses the predictions into a final annotated output.

Development was carried out in a Windows + WSL workflow, with the edge-facing Stage A designed around Jetson-class deployment and the heavier segmentation stage trained/evaluated with GPU tooling.

Notebook-order pipeline

The page below follows the notebook order: Stage A video detection and stitching, followed by Stage B segmentation, final fusion, metrics, and interpretation.

Stage A — Jetson video detection: process a region of interest, isolate motion with frame differencing, extract EfficientNet features, reduce them with PCA, classify log/no-log frames with an SVM, and group positive frames into log intervals.
Stitching: consecutive positive frames are horizontally stitched into full log images that represent the visible passing log surface.
Stage B — GPU segmentation: split stitched logs into overlapping halves, segment the log boundary with YOLO, normalize crop height, run bark segmentation, restitch quarters and halves, then reconstruct a unified final log boundary.
Final output: white bark outlines plus a red unified log boundary over the stitched log body.
Stage A — Jetson: Video → Stitched Logs

1. Region of interest and frame differencing

The first stage reduces the video problem to the area where logs appear. Consecutive frames are differenced so the moving log is emphasized while the mostly static background is suppressed.

2. EfficientNet features, PCA, and SVM classification

A frozen EfficientNet model acts as a feature extractor. The features are standardized, reduced to four principal components with PCA, then classified with an RBF-kernel SVM to produce a frame-level log/no-log signal.

SVM decision-score note: the decision plot should be interpreted with the labelling process in mind. Some frames are labelled from the full log interval, but the region of interest can lag slightly behind the full-frame log presence. A few blue points crossing the threshold are therefore acceptable in this context, because the downstream interval grouping and stitching logic is tolerant to small frame-level ambiguity.

3. Log interval detection and frame stitching

Consecutive positive predictions are grouped into log intervals. Frames inside each interval are stitched horizontally to reconstruct the passing log surface.

Stage B — GPU: Stitched Log → Log Boundary + Bark Segmentation

4. Log segmentation setup

Stage B uses YOLO segmentation models. One model predicts the outer log boundary, while a second model predicts bark surface fragments. The log segmentation stage starts with polygon annotations and overlapping half-splits.

5. Half split with overlap

The stitched log is split into left and right halves with a small horizontal overlap. The overlap helps prevent boundary discontinuities at crop edges where segmentation models can become less reliable.

6. Greenify and unified height cropping

After log segmentation, polygons are converted to masks, smoothed, and used to crop both halves to a shared top/bottom height. Non-log areas are filled with a uniform light-green background to prepare the image for bark segmentation.

  • Convert YOLO log polygons to binary masks.
  • Morphologically smooth the log mask.
  • Find the bounding rectangle of the log.
  • Use shared top and bottom crop bounds across both halves.
  • Fill non-log background with a consistent light-green value.
  • Save offsets so polygons can be aligned again during final fusion.

7. Bark segmentation setup

Bark segmentation uses polygon masks for bark fragments. Each normalized half is split again into quarters, increasing effective resolution for texture-level bark detection.

8. Bark restitching and final fusion

Bark quarter predictions are stitched back into halves. The overlap is removed, right-side predictions are aligned, and saved offsets are used to reconstruct the original geometry.

  • Left/right bark quarters are restitched into bark-annotated halves.
  • The 3% overlap is removed before final log reconstruction.
  • Right-side polygons are shifted into full-log coordinates.
  • Log polygons are converted into Shapely geometries and merged with union.
  • The final boundary is rasterized, smoothed, and drawn in red.
  • Bark outlines are rendered in white over the stitched log body.

12. Explainability and model behaviour

Why frame differencing helps

The conveyor background is mostly static while logs move through the frame. Differencing consecutive frames suppresses background information and emphasizes motion, making the log/no-log classifier easier to train.

Why some SVM score points cross the line

Some blue points above the decision line were acceptable because labels were based on broader frame/log-interval timing, while the ROI did not always show the log clearly at the same moment. The interval grouping stage is tolerant to this kind of small frame-level ambiguity.

Why PCA + SVM is useful on edge hardware

EfficientNet features are high dimensional. PCA compresses them into a small representation, and the SVM performs lightweight binary classification suitable for Jetson-class deployment.

Why overlap is used for segmentation

Large stitched logs are split for segmentation. A small overlap reduces boundary failures near crop edges and helps preserve continuity when the halves are merged.

Why Phase 2 is the best checkpoint

Phase 2 gives the strongest balance of high precision, high recall, and strict mAP. Phase 3 remains strong early but shows later instability, so best-checkpoint selection is more important than final-epoch reporting.

13. What this project demonstrates

End-to-end ML pipeline design

The project combines video processing, feature extraction, classical ML, neural segmentation, post-processing, and final visualization.

Hybrid classical + deep learning approach

Instead of using one model for everything, the system combines EfficientNet, PCA, SVM, YOLO segmentation, morphology, and geometric union.

Industrial computer vision framing

The pipeline is built around a real inspection-style problem: detecting logs, preserving full-surface geometry, and identifying bark regions.

WSL-based development workflow

The project was developed in a Windows + WSL environment, with Python-based ML tooling and GPU-oriented segmentation workflows separated from the Jetson-facing edge deployment concept.
