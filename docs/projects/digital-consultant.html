Agentic Digital Consultant

A stateful, multi-turn AI consultant built for a New Zealand AI consultancy. The system classifies user intent, maintains conversation state, delivers contextual pre-scripted video responses, guides users through a structured consultation form, verifies email ownership with confirmation codes, and submits qualified leads to the business.

Project summary

This project automated the initial consultation path for an AI consultancy. Instead of a static contact form, the website used an AI-driven assistant that could greet visitors, understand what they wanted, answer service questions, transition into a guided consultation, collect structured business-problem details, verify the user's email, and send the completed lead to the business.

The key design decision was to combine flexible LLM-driven intent classification with deterministic state management. The model handled natural language interpretation, while the application controlled form progress, validation, video selection, email confirmation, and final lead submission.

The project was completed and deployed during September–December 2024. The full source is private because it was built as a client/business project, but the architecture, flow, and implementation approach are summarized here.

System architecture

The system was built as a full-stack agentic web application with a FastAPI backend, LangChain/OpenAI intent layer, thread-safe state management, async email verification, structured logs, and a Nuxt/Vue frontend with synchronized video playback.

FastAPI backend

Served the assistant endpoints, handled user messages, coordinated state, triggered video responses, advanced consultation stages, and managed lead submission.

LangChain + GPT-4 intent layer

Classified messages into intents such as greeting, consultation, services, information, thanks, goodbye, and unknown while tolerating natural language variation and typos.

Custom state machine

Maintained per-thread dialog state, form stage, user details, greeting state, finalization state, and last-active timestamps for cleanup.

Video response system

Served contextual pre-scripted videos mapped to conversation states and form progress, giving the assistant a richer presentation layer than text alone.

Email verification system

Sent confirmation codes through SMTP, validated user email ownership, and only finalized consultation submissions after successful code verification.

Nuxt 3 / Vue frontend

Provided the chat interface and synchronized video player, connecting the user experience to the backend assistant state.

Core conversation flow

The application worked as a stateful consultation funnel: natural chat at the surface, deterministic workflow control underneath.

1. User greeting / initial message: the assistant greets the visitor, classifies intent, and determines whether the user wants service information, a consultation, or general help.
2. Intent classification: GPT-4-based prompts classify the message into supported intents such as greeting, consultation, info, services, goodbye, thanks, or unknown.
3. State update: the backend updates the user's thread/session state, including dialog state, form stage, collected user details, last active time, and finalization status.
4. Contextual video selection: the system maps the current state to a relevant pre-scripted video such as welcome, consultation stage, confirmation code, or goodbye.
5. Guided consultation form: if the user wants a consultation, the assistant collects structured business requirements through a staged form.
6. Email confirmation: the user provides an email address, receives a confirmation code, and must enter the code before the lead is finalized.
7. Business handoff: after verification, the backend sends the completed consultation details to the business email for follow-up.

Consultation form engine

The consultation flow collected structured information needed to qualify an AI solution request. The LLM provided conversational flexibility while the state machine kept the form deterministic.

Stage Information collected Purpose

3 Problem type Classify the nature of the AI/automation opportunity.
4 Data format Understand whether usable data exists and what shape it is in.

Key technical highlights

Stateful agent design

Each conversation maintained a separate thread state, allowing the assistant to continue form collection and route responses based on prior progress.

Intent routing

GPT-4 was used to classify what the user wanted, but the backend controlled what the application did next. That separation reduced random behaviour.

Deterministic form progression

The consultation process followed a known state machine with validation, cancellation support, edge-case handling, and finalization rules.

Video-enhanced UX

Pre-scripted videos were mapped to assistant states, giving the site a more polished front-facing consultant experience without requiring real-time avatar generation.

Email verification

Confirmation codes helped prevent unverified form submissions and created a cleaner lead handoff process.

Structured logs

The backend logged conversation activity and internal system events, improving observability and debugging for a multi-turn assistant workflow.

Security, validation, and operational behaviour

Input validation

The form flow validated structured inputs such as email and confirmation code before finalizing the consultation submission.

Thread cleanup

Inactive conversation threads were cleaned after a timeout, preventing abandoned sessions from accumulating indefinitely.

Rate-limiting ready

The design included production-facing concerns such as security headers, CORS, sanitization, and rate-limiting readiness.
